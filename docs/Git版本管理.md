# Git 版本管理

仓库：<https://github.com/2023liushuya-lab/mizzen-fgd-prototype>。这是独立的前端原型仓库，正式 Mizzen 研发仓库不受影响。

## 产品同学最简单的用法

平时仍在 Codex 中说明要改的页面并查看固定本地预览，不需要自己输入 Git 命令。可以直接说：

- “把这次改动保存到 GitHub”：提交当前任务分支、同步远端并更新 PR。
- “这版确认了，合并为评审版”：检查通过后合并到 `main`，按需添加明确的版本标签。
- “比较这版和上一版”：通过 PR 或提交记录查看改动。
- “撤回某一次改动”：建立回退提交和 PR，保留历史，不强制覆盖远端。

GitHub 保存代码和记录；本地尚未提交的修改不会自动上传。GitHub 仓库地址也不等于可供同事访问的在线预览站点。

## 分支与提交

`main` 保留已确认的基线；每次独立任务在 `codex/简短任务名` 分支修改。修改后提交到远端并创建 PR。未经用户确认，不自行合并主分支。

一次提交处理一类改动，提交说明写明影响的页面与行为。共享布局、题型或状态调整需要标注受影响角色。不要把多个 Agent 的无关改动一起提交。

## 自动检查与交接

PR 和 `main`／`codex/**` 分支更新会运行 GitHub Actions，检查锁文件安装、格式、TypeScript、行为测试与构建。CI 通过仅表示这些工程检查通过，界面仍需浏览器走查。

研发交接时提供 PR、提交号或确认后的版本标签，确保使用同一版源码。当前原型仍使用本地状态与示例媒体，真实服务接入边界见 README。

不提交依赖、构建缓存、环境密钥或浏览器个人演示数据。保留 `.gitignore` 和锁文件；不使用强制推送覆盖已有评审记录。
