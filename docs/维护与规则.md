# 维护与规则

## 代码格式

日常改动以 TypeScript 源码为准。`.tsx` 描述界面，`.ts` 描述类型、数据与动作，CSS Modules 控制局部样式，Markdown 存产品口径和验收记录。字体是单独的 WOFF2 文件，不在每个页面重复内嵌。

不要直接修改 `.next/` 或以后产生的交付包。路由文件只负责装配页面，业务放在 `features/`；共用题型放在 `features/questions/`，避免主持台与旁听室各写一次。现有题目按 standard question、raw results、analysis、image results、answer form、annotation editor 分文件，配置页也将名单和圆桌分开维护。

## 数据流

`types/` 定义对象 → `lib/prototype-repository.ts` 保存本地命令 → `lib/fgd-reducer.ts` 执行业务规则 → `stores/fgd-store.ts` 提供动作与选择器 → React 展示。普通模块只通过 props 与回调通信。后续接正式 API 时替换本地数据适配，不需要再重写三套 UI。

本地命令日志每条使用独立的 key，多个角色窗口提交时不会依靠覆盖整个旧文档来同步。日志仅用于原型，不能代替服务端鉴权、跨设备网络或多人编辑冲突解决。

## 保留的关键口径

- 主持人控制开始和切题；超时不自动切题；无暂停、邀请和共享屏幕。
- FGD 有独立标注题，与图片上传题分开；支持 11 个展示类型，其中陈述题无需作答和分析。
- 大纲章节有分钟，访谈指引默认展开。三端题目 ID 稳定，展示顺序不作为数据主键。
- 主持人可回看未开始题；受访者只收到已开始的当前题；旁听者只浏览已开放的历史和当前内容，提交后即时更新。
- 前题投放展示前题全员汇总与当前题结果，受访者的投放区不包含主持人的 AI 分析。
- 旁听者看到完整研究内容、AI 总结／追问和发言占比，无会控权。线上可切换题目视图与视频视图；线下可切换题目视图与现场画面。
- 小纸条是旁听者唯一上行动作。线上与线下旁听室均在右侧展示统一的「递小纸条」整体卡片，无需填写署名、无需关联题目；主持人端直接将旁听室发来的小纸条展示在右侧「发言占比」下方的「话题追问」卡片中，并用专属徽章与底色同 `✧ AI` 追问区分。
- 线上与线下均提供底部栏左右切换题目的按钮；现场画面保持纯净全景视图，不展示受访者个人信息。
- 结束后旁听转只读复盘，保留题目、回答、字幕和分析，可导出本人纸条／草稿；受访者入场关闭。
- 章节拖动保留旧讨论分段，已经发生的 A 章时间与字幕仍在 A；当前题移到 B 后新讨论计入 B。移除人员保留既有研究记录。
- 当前视觉沿用用户已确认的暖米白 + Mona Sans；迁移仅调整代码组织，不借机换皮。

## 原型与正式功能

当前总结和追问使用本地规则演示，基于实际文字和前题相关内容，不调用 LLM。正式 AI 接入时需明确提供用户已录入背景、相关前题回答、当题作答／标注与逐字稿；需要给出来源，证据不足不编造。媒体和网络图标同样是示例，不能据此声称真实 WebRTC、ASR 或录制已经上线。

## 改动后的验证范围

文字或样式改动检查受影响页面和小屏布局即可；题型或业务动作改动运行 `pnpm check` 并走对应角色联动；交付前运行一次 `pnpm build`。不要每次调整 2px 都重跑全流程、重新打包旧 HTML。

## FGD 大纲创建界面（2026-11-10）

参考当前 Mizzen 前端 `create/edit/components/InterviewEditor.tsx` 的章节内编辑结构，以及 `create/edit/page.tsx` 的编辑／实时预览双栏布局。此原型使用原有暖米白与 Mona Sans；仅修改原型仓库，不修改正式业务仓或历史 HTML。

- 左侧按章节直接展开编辑，右侧同步受访者预览；窄屏用编辑／预览切换。
- 每个章节标题旁配置预计用时（分钟），顶部汇总全大纲时长；保存后进入新场次的章节时间配置。
- 访谈题不提供深度追问、浅度追问或自动追问档位；访谈指引保留，供主持人参考。
- 标注题是独立题型，蓝色喜欢、红色不喜欢、黄色困惑；与图片上传题分开。预览标注为临时试画，不写入受访者作答。
- 题目可在章节间拖动，保留题目 ID。类型切换重置原题型专属选项，避免标注题残留选择题选项。已有场次快照不随项目草稿修改。
